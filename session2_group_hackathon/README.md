# Session 2 — Group hackathon (17:10–18:10)

Teams of 4 (2 clinician scientists + 2 bioinformaticians). 60 minutes to build, then a 5-minute pitch/demo each at 18:10.

## Menu

| Track | Focus | Core question |
|---|---|---|
| [1 — Case review UI](track1_case_review_ui/) | Front-end, broad | What would make this report actually usable in a real case review? |
| [2 — Explanation card](track2_explanation_card/) | AI-native, focused | What should a diagnostic scientist see when reviewing one prioritised candidate? |
| [3 — NL query layer](track3_nl_query_layer/) | AI-native, backend+UI | Can you ask Talos output questions in plain English? |
| [4 — Triage / prioritisation](track4_triage_prioritization/) | Algorithm/policy | Of 5,000 unsolved genomes, which get reanalysed first? |
| [5 — Open pitch](track5_open_pitch/) | Wildcard | Your own idea, same theme |

Tracks 1–3 all draw on [`../shared_data/mock_talos_candidates.json`](../shared_data/README.md). Track 4 has its own case-level dataset.

Judged on the [rubric](../docs/judging_rubric_and_scoring_sheet.md) — primarily clinical usefulness and novelty.

**Scope tip for all tracks:** you will not finish a "complete" version in 60 minutes, and that's fine. A working prototype of a well-scoped slice beats a fake/mocked-up version of the whole thing — the rubric rewards real over complete.
